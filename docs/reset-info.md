# Отчёт предыдущего программного перезапуска

`reset-info` читает отдельный штатный отчёт A.04.02 через фиксированную команду
`sysShowResetInfo` без аргументов. Это ещё один источник диагностики рядом с
[LCD, системным журналом и историей головок](capabilities.md).

**Состояние подготовки:** реализация, проверка официального образа, отказы на
повреждённых ответах и веб-представление проверены офлайн и на BTT без USB I/O.
Живой вызов на HP ещё не выполнен: он запланирован после завершения отдельной
серии устойчивости. Найденная команда не объявляется уже полученными данными.

## Что может ответить HP

При действительной сигнатуре сохранённого отчёта native-код выводит:

```text
Calling code: 0x...
Kernel state: 0x...
TID: 0x...  PRIO: 0x...
Name: ....
```

Вместо задачи возможны `Called from ISR` или `Invalid TID`. Без действительной
сигнатуры ответ буквально `Not sysReset valid info`. Дополнительная штатная
строка `Raier Dw was not in reset` сохраняется без придуманной расшифровки.

`Calling code` — сырой аргумент, сохранённый путём программного сброса. Он не
объявляется адресом инструкции или расшифрованной физической причиной.
Наличие отчёта не доказывает его связь с нынешней ошибкой; отсутствие записи
не означает отсутствия аппаратных или других системных ошибок. Времени события
в этом формате нет. Четыре байта имени задачи сохраняются даже при
непечатных символах.

## Как ограничен доступ

План состоит из восьми запросов: firmware и serial, четыре ограниченных чтения
полного wrapper/native-кода, один getter, повторный serial. Перед getter код
по адресам `0xA026CF5C` (60 байт) и `0xA010C0E8` (290 байт) должен совпасть с
закреплённым официальным A.04.02. Диапазон общего чтения памяти не расширен на
адреса регистра отчёта. Произвольные вызовы функций не добавлены.

Парсер принимает весь ответ, его точную native-грамматику и свежую конечную
метку. Два последующих пустых этапа IN должны реально состояться. Старый хвост,
лишний текст, неполный отчёт или несовпавший код блокируют дальнейшие запросы.
Сброс `sysReset` и очистка `sysCleanResetInfo` не вызываются.

Веб-публикация читает только завершённый проверенный сеанс. `/api/reset-info`
и отдельный раздел страницы имеют собственное время чтения. Неизвестный смысл
не заменяется уверенной расшифровкой; текст вставляется как текст, без HTML.

## Отдельный запуск

Используйте [подготовленный локальный профиль](batch.md), пустую очередь и
свободный USB после остановки мониторов. Не запускайте это параллельно со
сравнительным опытом. `DEADLINE` задаёт разрешённый срок с часовым поясом.

```bash
python3 tools/service/batch_read.py reset-info --refresh-id --short-comment --until-utc "$DEADLINE"
```

После независимой приёмки исходного сеанса его небольшой кэш можно опубликовать
через `journal_view.py`, как и остальные журналы. Публикация кэша сама не
обращается к USB.
