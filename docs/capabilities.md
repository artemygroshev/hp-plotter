# Что мы видим и что ещё предстоит открыть

**Прочитаны полный LCD, 30 основных и 14 дополнительных полей, десять системных
событий и история четырёх цветов головок. Полный доступ ко всем функциям
плоттера не реализован.** Этот документ отделяет аппаратно проверенное
чтение от найденных в прошивке возможностей и плана дальнейшей работы.

## Дословное сообщение и причина ошибки

Для полезного отчёта нужны три разных слоя:

| Слой | Что показываем | Текущее состояние |
| --- | --- | --- |
| Сообщение HP | Сам LCD с предупреждением, значками и временем чтения | Работает, включая обе фазы мигания; автоматическая текстовая расшифровка любого экрана не реализована |
| Событие плоттера | Точный код и место события в firmware | Кольцо Error Log и история головок прочитаны; даты системных событий не подтверждены |
| Объяснение | Значение кода по HP и возможные физические причины | Для исследованного чёрного канала есть подтверждённый класс электрических ошибок; конкретная повреждённая деталь не установлена |

Надпись `Replace printheads` не означает «закончились чернила». Значение
`ERROR-STATE=0` тоже не означает Ready: в проверенном снимке одновременно
присутствует предупреждение LCD о головке. Отчёт должен сохранять эти источники
раздельно, с возрастом, сырым значением и происхождением расшифровки.

В веб-просмотр добавлены отдельные таблицы системных событий и головок со своим
временем чтения. Для заранее сверенной пары
LCD-буферов он показывает `Replace printheads` и отметку Black; для точного
`PH-STATUS-3=524288` на A.04.02 отдельно выводит вычисленный 0033 с оговоркой
о вычислении из маски. Неизвестному экрану текст не назначается,
другой firmware или недоступному/другому статусу код не назначается. При
отсутствующем снимке прежняя расшифровка очищается. Это ограниченное распознавание
проверенного состояния, не OCR всех экранов.

### Что известно о чёрной головке

Следующие сведения об электрическом коде относятся к прежним снимкам.
В [отдельном чтении 11 ноября](black-output-check.md#свежие-статусы-после-пустого-повтора)
маска Black стала `0x0100000a`, без прежнего бита `0x80000`; текущий 0033
из неё не выводится. После одного восстановления и двух тестов пользователь
подтвердил пустые листы. Конкретная физическая причина ещё не установлена.

На проверенных снимках LCD: `Error Select / Replace printheads`, мигающий крест
на Black. Прочитанное значение `PH-STATUS-3 = 524288 = 0x80000` переводится
функцией A.04.02 `0xA00EF4AC` в подкод 33. HP относит 30–33 к электрическим
ошибкам головки: сервисное руководство, стр. 3-23.

Дополнительный офлайн-разбор `0xA00EF628` и таблицы `0xA039D324` для **этой
точной маски** даёт полный вычисленный код **0033**. Позже та же маска прочитана
из текущего слота истории Black и совпала с отдельным текущим ODB-статусом.
Четырёхзначная строка остаётся **вычисленной штатным алгоритмом из сохранённой
маски**, а не отдельной строкой, хранящейся в журнале. История других слотов
не объявляется нынешней причиной остановки.
Отсутствие бита `0x8` выбирает в этой функции группу кодов «in warranty»;
это флаг алгоритма HP, не подтверждение действующей гарантии в календарном году.

При этом важно не перепутать три порядка:

| Цвет | Суффикс ODB `PH-STATUS-*` | Индекс устройства в функции кода | Цветовой префикс кода | Место значка LCD слева |
| --- | --- | --- | --- | --- |
| Cyan | 0 | 1 | 02 | 1 |
| Magenta | 1 | 2 | 01 | 3 |
| Yellow | 2 | 3 | 03 | 4 |
| Black | 3 | 0 | 00 | 2 |

По одному коду нельзя различить саму головку, её контакты и электрический тракт
каретки. Совместимость новой партии HP 11 со старой firmware — дополнительная
проверяемая гипотеза, а не установленная причина. Расшифровка не исправляет
головку и не доказывает причину прежней цветной ряби.

Для `WS-B-ERROR=16` найдена статическая связь в A.04.02: обработчик
`0xA00FB3D0` объединяет `PH-STATUS-0…3` операцией OR и проверяет маску
`0x04FEFFE1`. При ненулевом результате он через `0xA007B430` выставляет бит 4
в `WS-B-ERROR`. Инициализация `0xA00FB4F4` содержит тот же путь.
Поэтому это сводный признак ошибки головок, согласующийся с прочитанными
значениями, а не ещё одна установленная физическая неисправность. Код этих
дополнительных функций исследован офлайн; новые вызовы на HP не выполнялись.

Также аппаратно проверен отдельный [читатель отчёта программного перезапуска](reset-info.md).
Он получил буквальное `Not sysReset valid info`: действительной записи software
reset нет. Чтение не очищает отчёт, не заменяет системный Error Log и не входило
в уже идущую серию LCD/44 полей.

## Карта возможностей

| Область | Что подтверждено | Незакрытая часть |
| --- | --- | --- |
| LCD | 128×64, основные проверочные копии и фаза мигания | Обновление быстрее полного последовательного чтения; любой меняющийся экран |
| Идентичность и статус | Основные 30 и дополнительные 14 полей реально прочитаны | Неизвестные enum, реальный прогресс задания, подтверждение всех единиц |
| Системные ошибки | Прочитаны все 10 записей: код, имя файла, строка; две копии кольца совпали | Date field нулевой; сопоставление с физическим меню не выполнено |
| История головок | Прочитаны пять слотов каждого цвета, 14 заполненных записей; расход, дни, cleaning level, маска и вычисленный код | Сравнение с физическим меню; достоверность календарного возраста и диагностика конкретной детали |
| Предыдущий software reset | Отдельный план 8 запросов принят на HP; ответ `Not sysReset valid info` | Действительный отчёт задачи не получен; значение Calling code и дата события неизвестны |
| Температура, датчики и ресурс | Есть команды и объекты-кандидаты | Разбор побочных эффектов, параметров и единиц, затем ограниченная проверка |
| Прогресс задания | Доступны сведения CUPS на BTT | Принятое плоттером задание, стадия обработки и физический выход бумаги не подтверждены |
| Кнопки и меню | Один Enter и фрагмент Ink menu прочитаны в одном Tcl job | Новый служебный job возвращает страницу состояния; постоянная навигация пока не принята |
| Калибровки и обслуживание | Выполнен один native recovery уровня 0; получен маркер возврата | Отдельная K-очистка, автоматический полный цикл и восстановление физических сопел не подтверждены; [подробности](cleaning-control.md) |
| Flash и полный инженерный доступ | Перепрошивка для полученного чтения не потребовалась | Произвольное управление всеми функциями не реализовано и не доказано |

Само наличие команды не доказывает её применимость к DesignJet 500 без
formatter-карты. Например, функции formatter/HDD могут относиться к другому
исполнению семейства. Аналогично `fpGetStatus` не возвращает текст ошибки:
проверенный обработчик `0xA027C068` сводит результат вложенной функции к 0/-1.

## Реализованный путь к журналам

В сервисном руководстве HP, стр. 2-5…2-6, Error Log содержит последние десять
системных ошибок, код, место возникновения в firmware и дату. Стр. 3-15…3-16
описывают историю пяти головок каждого цвета. Это системные события и история;
старую запись нельзя автоматически выдавать за текущую причину остановки.

Статически для A.04.02 найдены:

| Объект | Адрес/параметры | Граница доказательства |
| --- | --- | --- |
| Чтение записи системной ошибки | `0xA0295818`, группа 8, теги 811…820, запись 20 байт | Код и формат разобраны; сама функция на HP не вызывается |
| Индекс кольца системных ошибок | Тег 810 | Порядок берётся из RAM и алгоритма меню, newest first; физическое меню ещё не сверено |
| История головок | `0xA00F6354`, теги 822…841, запись 15 байт | Формат прочитан через RAM; функции EEPROM не вызываются |
| Кандидаты чтения EEROM | `eeReadEeromMem`, `eeReadEeromByteArray` | Нужно подтвердить имена узлов, теги, длины и выходной канал; по имени команды запускать нельзя |

Реализованы два ограниченных плана: `journal` и `head-journal` в
[`batch_read.py`](../tools/service/batch_read.py). Они используют существующее
MAIN RAM-зеркало: группа 8, заголовок `0xA03A0F10`, версия таблицы 6. Кольцо
начинается со смещения 1426 и занимает 201 байт; история головок — со смещения
1627, 302 байта с упакованными индексами. Закреплены машинный код, дескрипторы,
геометрия и границы. Читаются две полные копии, затем повторяются заголовки и
serial. Изменившиеся или неизвестные данные отвергаются.

В конфигурации таблицы байт +10 является отдельным рабочим флагом: в файле он 0,
на живом HP — 1; это не версия +9. В цветовой таблице +4 каждого 22-байтового
элемента хранит рабочий ODB handle; он проверяется отдельно от постоянных полей.
Первые строгие отказы на этих отличиях сохранены как отказы собственной схемы
проверки, а не ошибки транспорта.

Для кодов головок перенос алгоритма сравнен с независимым интерпретатором
исходных машинных инструкций: одиночные, парные и 4096 случайных масок,
четыре цвета. Физическое сравнение журналов с меню HP ещё не выполнено.
Функции записи, очистки, сброса счётчиков и инициализации EEROM не нужны.

При разборе уже найдены две причины не использовать готовые команды вслепую.
`eeReadEeromByteArray` вызывает `0xA02753FC`, который выводит массив через `%s`:
двоичная запись обрежется на первом NUL. `eeReadEeromByteArrayElement` вызывает
`0xA027550C`, возвращающий 0 также при ошибке чтения, без отдельного признака
успеха в Tcl-ответе. Будущий читатель должен отдельно проверять код результата
чтения и точное число двоичных байтов; реализованный клиент обходит эти команды
чтением проверенного RAM-зеркала. Статическая таблица имён даёт `MAIN` →
группа 8 и `BACKUP` → группа 9; доступ к резерву не означает разрешения его
изменять. Кроме того, getter индекса истории `0xA00F6158` сам пишет EEPROM,
если индекс недопустим. Он намеренно не вызывается: клиент сохраняет такой
индекс без исправления. Адреса и хеши путей включены в офлайн-каталог.

Для удалённых кнопок нужен отдельный режим: прочитать исходный экран → выполнить
одно осмысленное действие → дождаться и проверить новый экран. Слепая длинная
последовательность нажатий не обеспечивает управления: у того же Enter действие
зависит от текущего меню. Кнопки и новые запросы не добавляются в уже идущую
сравнительную серию устойчивости транспорта.

## Дополнительные состояния: отдельный режим

Режим `diagnostics` выполняет 14 фиксированных чтений ODB для
ошибок peripheral/mechanical/media/writing-system/PDL/spooler/RMC и состояний
intervention/cover-open/paper-jam/busy/printing. Он проверяет firmware и serial
до чтения, затем повторяет serial в конце. Обычный `all` и монитор продолжают
использовать прежние 30 полей.

**Все 14 полей прочитаны двумя отдельными способами обмена.** Получены
PERIPHERAL-B=1, WS-B=16, INTERVENTION=1, остальные 11 значений — 0. Неизвестные enum не
переводятся в названия физических неисправностей. Для двух длинных имён
используется штатный тип объекта без необязательного аргумента `type`.
Самое длинное чтение помещается ровно в 129 байт без padding-комментария;
все B/R/E-метки и строгая проверка ответа сохраняются. Старые 76 вариантов
коротких запросов 128/129 побайтно совпадают с проверенной v5.

После подготовки профиля 129 и безопасного окна без сравнительной серии
используйте явно заданный дедлайн:

```bash
python tools/service/designjet_readonly.py diagnostics --until-utc "$DEADLINE"
```

Режим не читает EEROM, не нажимает кнопки и не запускает обслуживание. Его новые
значения не подмешиваются в старую 30-полевую серию. Для отдельного 44-полевого
монитора предусмотрен новый [batch-план](batch.md). Его устойчивость проверяется
отдельно от факта чтения каждого поля и журнала.

## Воспроизводимый офлайн-каталог

[a04-capabilities.json](a04-capabilities.json) содержит 403 регистрации команд
одного проверенного машинного шаблона, адреса обработчиков, заметки о проверке,
хеши ключевых функций и таблицу индексов головок. Это **не полный API firmware
и не список безопасных команд**. Большинство обработчиков ещё не исследованы.
Утилита не строит произвольный исполнитель и не обращается к устройству.

```bash
python tools/firmware/capability_map.py /private/engine-A0402-main.bin
```

Нужен внешний официальный main-образ с SHA256
`c882e68d2eb2462745f1ec984ce8f5ed745d2900587dce6b36acee5b89a1f4eb`.
Другой или изменённый файл отвергается. Сырые строки из другой версии не
используются как адресная карта A.04.02. Образы HP в Git не добавляются.

Первичные источники: [руководство пользователя HP DesignJet 500](https://h10032.www1.hp.com/ctg/Manual/c00748239.pdf),
[сервисное руководство HP, разделы 2 и 3](https://www.laserexpressinc.com/manuals/HP/hp-dsj-500-510-800-series-service-manual.pdf),
[HP 11 Printhead Errors](https://support.hp.com/za-en/document/c06098737),
официальный A.04.02 с [проверенными хешами](../tools/firmware/official-engine-images.json).
