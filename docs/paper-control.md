# Тип бумаги самого HP

`tools/service/paper_control.py` — отдельный инструмент для исследованной
связки C7769B / A.04.02 / USB–parallel. Он предназначен для смены профиля
в самом HP; игнорируемый `MediaType` в CUPS не используется.

**Статус: экспериментальный, аппаратная приёмка не завершена.** После
восстановления отдельно прочитан фактический **Plain Paper**. Следующая
попытка применения остановилась до setter: вместо свежего FW-ответа пришёл
задержанный ответ предыдущего чтения головки. Строгая проверка nonce его
отклонила. Запись типа бумаги пока не выполнена и не объявляется работающей.
GUI и его кнопка обновления не вызывают этот инструмент; постоянный опрос
не запускается.

## Подготовленный способ

В A.04.02 зарегистрирована команда `sysODBSet name value ?type?`. Реализован
только фиксированный вызов `FP-MEDIA-NAME` со строковым типом `s`. По коду
прошивки изменение этого объекта вызывает обработчик, который при наличии
бумаги и внутреннем `MEDIA-INPUT-TRAY=0` обновляет `PRINT-MED-TYPE`.
[Адреса, SHA256 функций и каталог HP](paper-control-evidence.json) подтверждают
статический путь, а не успешное изменение на устройстве.

| Аргумент | Имя в HP | Фактическая бумага |
| --- | --- | --- |
| `plain` | Plain Paper | Обычная бумага без покрытия |
| `coated` | Coated | Бумага с покрытием |
| `heavy-coated` | Heavy Coated | Плотная бумага с покрытием |

Матовая поверхность сама по себе не определяет наличие покрытия. Для обычной
матовой бумаги **без покрытия** нужен Plain Paper. По [описанию HP](https://support.hp.com/us-en/document/bpp03041)
при выбранном glossy чёрные блоки Diagnostic Print A не печатаются.

## Запуск после проверки транспорта

Используется приватная конфигурация локального root executor, как для batch:
закреплённые machine-id, дескрипторы адаптера, serial HP, общие USB-lock/guard
и явный none/alt0/129 профиль. Нужна libusb, дополнительных Python-пакетов
на BTT нет. Окно операции ограничено 90–900 секундами; `DEADLINE` — ближайшее
время завершения в ISO8601 с часовым поясом. Из комплекта проекта:

```bash
# Только чтение — режим по умолчанию
sudo env HP_PLOTTER_CONFIG=/etc/hp-plotter/config.json \
  python3 -B tools/service/paper_control.py --until-utc "$DEADLINE"

# Явный выбор обычной бумаги
sudo env HP_PLOTTER_CONFIG=/etc/hp-plotter/config.json \
  python3 -B tools/service/paper_control.py --set plain --until-utc "$DEADLINE"
```

План подтверждает firmware и serial, читает занятость, внутреннюю печать,
наличие бумаги, лоток, производителя и прежний тип. Запись допускается при
флагах занятости 0/0, наличии бумаги 1, внутреннем лотке 0, vendor HP и известном
исходном профиле его каталога. Если нужный тип уже выбран, записи нет.
Для отдельной явной проверки записи того же профиля есть `--reapply`, только
вместе с `--set`. При совпадающем значении `changed` остаётся `false`.
Отдельная пробная попытка без class ID между каждым чтением также не получила
свежего ответа. В публикуемом кандидате сохранён ID перед каждым запросом;
исправлением транспорта ни один из этих режимов не объявляется. Условия
прежних сравнительных серий не менялись.

Setter передаётся один раз в отдельном 129-байтовом кадре. Начальная B-строка
отсутствует, но обязательны свежие R/E с уникальным nonce и две пустые фазы
после ответа. Затем проверяются новое имя, неизменный vendor и serial.
Произвольных команд, клавиш панели, загрузки/отреза бумаги, очистки головок,
печати и сброса здесь нет.

## Отказы и границы

Перед каждой транзакцией проверяются очередь и владелец USB. Частичный OUT,
старый ответ, несовпадение чтения и незавершённый cleanup не повторяют setter
автоматически. При неподтверждённой записи остаётся device-side guard: он
останавливает и последующие задания backend до разбора сохранённого отчёта.
Удаление guard вслепую не является восстановлением обмена.

Отчёт `paper-control-*.json` содержит прежнее и новое значения, сырые флаги,
пакеты, USB-трассу и результат восстановления. Офлайн-тест или совпадение строки
без аппаратной приёмки не доказывают смену эффективного профиля. Сохранение
после выключения питания и физическое качество печати пока не проверены.
