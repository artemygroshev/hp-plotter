# Как читается экран

Путь: управляющий Linux-компьютер → закреплённый SSH → BTT/CB1 → libusb → USB–parallel 1a86:7584 → IEEE-1284 → HP C7769B.

Штатный USB-B самого плоттера и USB-сторона отдельного parallel-моста — разные тракты. Полученное чтение относится ко второму. Оно не доказывает ремонта native USB-порта.

## Проверка каждого запроса

1. Подтвердить machine-id BTT, единственный адаптер с закреплённым SHA дескрипторов, usblp/alt1, пустые Get-Jobs/lpstat и отсутствие USB backend/открытых дескрипторов.
2. Получить корректный IEEE-1284 ID именно HP DesignJet 500 (C7769B). Только явный нулевой ответ допускает один повтор; ошибка, чужой ID или частичный OUT не повторяются.
3. Передать один фиксированный 128-байтовый Tcl/PJL запрос. Полные 64-байтовые PJL COMMENT продвигают выдачу старых буферов и не запрашивают нового ответа.
4. Принять точный формат ответа с уникальным nonce. После конечной метки дождаться двух пустых фаз. Обычный возврат своего OUT не считается ответом HP.
5. Закрыть дескрипторы и собственный usbmon, восстановить исходный alternate/драйвер, перепроверить очередь и устройство.

Большие ответы в исследованном тракте приходили с задержкой и лишними блоками; собственный OUT встречался в IN, что также наблюдалось usbmon. Точное место дефекта между контроллером/DMA, мостом и HP не установлено. Удалять «похожие лишние 64 байта» из BMP и объявлять картинку исправной нельзя.

## A.04.02: native LCD

Перед вызовом фиксированного getter `0xA017D468` проверяются 96 байт его живого кода: SHA256 `0c8fc4be733ef9accb4911bfb6ce5466656aca2ebfff1d7484084dfdd6492538`. Сначала читаются версия и закреплённый серийный номер. Getter возвращает адрес descriptor, затем читается 12-байтовый big-endian заголовок width/height/data-pointer. Принимается только 128 × 64 и ограниченное выровненное окно heap RAM.

Пиксели: 1024 байта, четыре колонки по 64 big-endian uint32; старший бит слева, строка 0 сверху, 1 — чёрный. Читаются восемь участков по 128 байт через `osMemDump`. В ASCII dump каждый байт должен находиться ровно по своему адресу; пропуски, повторы и лишние данные отвергаются. Начальная отдельная B-строка иногда отсутствует; это явно фиксируется, а не объявляется успешным B/E framing. Для native dump требуются полное адресное покрытие, один свежий конечный nonce и отсутствие хвоста.

Указатели/заголовок/серийный номер сверяются после прохода. Два одинаковых основных кадра подтверждают стабильность в проверенном интервале, но не атомарный снимок постоянно меняющегося экрана.

FP root pointer находится по `0xA03A74B0`. В исследованной версии отступ `0x62A` содержит два указателя буферов, count, flashing flag и active index. Альтернативный буфер важен: крест на головке мигает, поэтому только фаза 0 может его скрыть. Частота мигания не восстановлена; произвольная анимация вместо настоящих фаз не создаётся.

## Подтверждённые результаты лаборатории

Основной буфер: `3073f0a291793adc93f24cbb7a81621b7408b1379664aed4dba123ef174cb689`.

Альтернативный: `e8ac29e01f47a4fd0030f627dfec9966bb039a15d298a939e65896cb9aae79bd`.

Различие — 52 пикселя крестика в прямоугольнике x=44…53, y=38…50. [Обычная фаза](../examples/panel-normal.png) и [мигающий крест](../examples/panel-blink.png). Текст: Error Select / Replace printheads.

По сервисному руководству HP, стр. 3-14, значки слева направо: Cyan, Black, Magenta, Yellow. Поэтому отмечена чёрная головка. Внутренние CMYK-индексы и порядок значков различаются: логический индекс Black равен 3.

PH-USER-STATUS = 0/0/0/2; PH-STATUS = 2/2/2/524288. Последнее для Black — `0x80000`. По офлайн-разбору A.04.02 функция `0xA00EF4AC` переводит этот бит в подкод 33. HP относит 30–33 к электрическим ошибкам головки (стр. 3-23). Это **вычисленный подкод**, а не прочитанный полный четырёхзначный код с панели; он не различает головку, контакты и каретку.

PH-MODEL = 0/0/0/0 — сырые enum. CRTGE-LEVEL = 0/0/87/0 не выдаются за проценты или физический объём в СНПЧ. ERROR-STATE=0, IO-STATUS-INK-OUT=3 и CUPS idle не отменяют предупреждение LCD. Тип форматирования `sysODBGet` не всегда меняет реальный тип ODB-объекта.

HP отдельно описывает несовместимость части новых HP 11 со старой firmware. Дата установленной головки неизвестна; применимость этого сценария не доказана. Источники — [здесь](sources.md).


## Влияние служебного job на меню

9 ноября одно нажатие Enter с последующим коротким чтением в том же Tcl job
показало Ink menu. Отдельное последующее чтение возвращало страницу состояния.
Таким образом, read-only относится к данным и настройкам, но не гарантирует
сохранение текущего фокуса UI. Постоянный Tcl-сеанс пока не принят: после
некоторых корректных ответов появлялся лишний управляющий символ. Полный
экран, фаза мигания, фрагмент и состояние до нового служебного job различаются.
Подробности и границы обслуживания — в [отчёте](cleaning-control.md).
