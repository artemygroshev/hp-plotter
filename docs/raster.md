# Проверка печатного потока

`tools/raster/decode_mode10.py` — офлайн-декодер PCL3GUI/Mode 10, соответствующего исследованному выходу Ghostscript cdnj500. Он не обращается к принтеру.

```bash
python tools/raster/decode_mode10.py /private/job.pcl WIDTH_IN_PIXELS /private/decoded.png
```

Ширину нужно брать из параметров конкретного растра, а не произвольно задавать 610 пикселей для бумаги 610 мм. При 600 dpi она зависит от полезной области и драйвера. Декодер проверяет границы строк, seed/delta, truncation и структуру команд. Это исследовательский разбор конкретного подмножества PCL3GUI, а не универсальный RIP.

В лаборатории исходный PDF и сохранённый вход CUPS совпали по SHA256. Повторный офлайн-RIP на x86_64 и arm64 дал одинаковый PCL3GUI. Восстановленные 53 774 388 пикселей совпали с эталонной растеризацией после нормализации младшего бита синего, который Mode 10 не сохраняет. Декодер отдельно сравнивался на 96 наборах строк с upstream-кодировщиком Ghostscript; чужой кодировщик здесь не включён.

Эти результаты исключают изменение проверенного PDF при доставке на BTT и подтверждают проверенный повторный RIP. Они **не доказывают**, что первоначальный OUT во время печати совпал с повторным, что parallel после моста был исправен или что HP одинаково понял всё обрамление потока.

Для разделения причин нужен внутренний диагностический рисунок HP с физической оценкой, затем небольшой внешний эталон с полным захватом OUT и изменением одного условия. Текстовый usbmon может обрезать payload, а даже полный захват USB не наблюдает сигналы parallel после адаптера. Старые испорченные большие плакаты автоматически не повторяются.

## Проверка влияния URI очереди

`compare_uri_filters.py` сравнивает программный RIP с исходным `usb://...` и
согласованным `hpplotter:/usb`. Он создаёт небольшой PDF с цветными полями,
запускает только `cupsfilter`/фильтры от пользователя `lp` в ограниченной
systemd-службе с `PrivateDevices=yes` и пишет приватные PRN. Задание CUPS и USB
backend не создаются. Настоящий `DEVICE_URI` явно задаётся каждому фильтру через
временные обвязки: одного `env DEVICE_URI=... cupsfilter` недостаточно для
исследованного CUPS 2.4.10. Системные фильтры и исходная PPD сохраняются.

Запускайте установленную копию на BTT в подтверждённом окне ожидания monitor,
при пустой очереди, с резервом минимум 180 секунд до разрешённого дедлайна:

```bash
sudo env HP_PLOTTER_CONFIG=/etc/hp-plotter/config.json \
  python3 tools/raster/compare_uri_filters.py \
  --settings /etc/hp-plotter/monitor.json \
  --backend-settings /etc/hp-plotter/backend.json \
  --until-utc "$DEADLINE"
```

Результат `rendered_bytes_identical` относится к двум сохранённым потокам и
данным параметрам. Он не проверяет провода, приём HP, сопла и физическую печать.
