# Быстрый старт

Сначала проверьте [совместимость и текущие ограничения](validation.md).
Для установки самостоятельного веб-просмотра на BTT используйте
[инструкцию службы](monitor.md). Здесь — разовый сбор через SSH.

## Установка на управляющем Linux-компьютере

```bash
git clone https://github.com/artemygroshev/hp-plotter.git
cd hp-plotter
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
make test
```

Команды этого раздела выполняются на управляющем компьютере. Нужен Python 3.9 или новее. На BTT требуются Python 3, libusb-1.0 и CUPS/ipptool; описание подготовки — [BTT и печать](btt.md). Одноразовый SSH-клиент исполняет необходимые модули в RAM. Для самостоятельного сбора на плате и просмотра LCD в браузере предусмотрены отдельные [локальные службы и согласование с CUPS](monitor.md). Локальному сборщику и веб-серверу достаточно стандартной библиотеки Python; Pillow на BTT им не нужен.

## Локальные параметры доступа

```bash
cp config.example.json config.local.json
chmod 600 config.local.json
```

Заполните `ssh_target`, закреплённый `known_hosts`, настоящий `machine_id` BTT и `printer_serial` HP. Шаблон специально не является рабочей конфигурацией. Ожидаемый SHA USB-дескрипторов относится к исследованному экземпляру/ревизии моста; сверяйте свой экземпляр, не заменяйте pin ради обхода ошибки.

Используется уже настроенный SSH key/agent и noninteractive sudo на выделенной плате. Проверка SSH-ключа обязательна, `StrictHostKeyChecking=yes`; автоматически доверять новому ключу клиент не будет. Не переносите ключи из чужой установки. Для существующего лабораторного входа по паролю можно указать `password_file`: отдельный файл владельца с правами 0600 вне Git, одна строка. Этот режим предполагает одинаковый пароль SSH/sudo; для иной схемы используйте key/agent. Пароль не помещается в JSON или командную строку.

Альтернативный путь к приватному JSON: переменная `HP_PLOTTER_CONFIG`. Репозиторий игнорирует `config.local.json`, `private/` и локальные захваты. Перед любым собственным push дополнительно проверяйте состав `git diff --cached`.

Общий `device_guard_file` находится на BTT и должен совпадать у SSH-клиента,
локального сборщика и CUPS-обвязки. Следующие две команды выполняются **на BTT**, при первичной подготовке
каталога владельца root, сохраняя уже существующие данные:

```bash
sudo install -d -m 0711 /var/lib/hp-plotter
sudo install -d -m 0700 /var/lib/hp-plotter/captures
```

Шаблон оставляет исходный профиль `small_query_bytes: 128`; отдельный опыт с 129
описан в [документации службы](monitor.md). Изменение профиля требует собственной проверки.

## Чтение экрана и статусов

Дождитесь пустой очереди. Клиент проверяет очередь/владельцев USB перед каждым
запросом и уступает заданиям. Для одновременной доступности печати установите
[CUPS-обвязку с тем же lock и guard](monitor.md). Если используется штатная
несогласованная очередь, остановите новые отправки на всё время чтения.

Укажите разрешённое время окончания текущего сеанса, например будущую дату в ISO8601 с часовым поясом:

```bash
DEADLINE='YYYY-MM-DDTHH:MM:SS+00:00'  # замените реальным будущим временем
python tools/service/designjet_readonly.py screen --passes 2 --include-blink --until-utc "$DEADLINE"
python tools/service/designjet_readonly.py status --until-utc "$DEADLINE"
python tools/service/designjet_readonly.py heads --until-utc "$DEADLINE"
python tools/service/designjet_readonly.py all --passes 2 --include-blink --until-utc "$DEADLINE"
```

`status` читает 22 основных поля, `heads` — восемь расширенных, `all` — экран и все 30. Результаты сохраняются локально в `tools/panel-live-YYYYMMDD/`: исходные ответы, JSON, native BIN, PNG и увеличенный PNG. Эти файлы приватные и исключены из Git.

Перед чтением RAM клиент проверяет A.04.02, серийный номер и 96 байт живого кода getter; адрес буфера определяется заново, старые адреса аллокаций не используются. Другая firmware/модель требует отдельного исследования. Кнопки, тестовая печать, прочистки и flash основной клиент не выполняет. Исторические низкоуровневые эксперименты сохранены как исходники; восстановление/reset не доступны из переносимого `run_service_read.py`.

Аппаратная проверка относится к одному C7769B/A.04.02 и одному экземпляру моста на BTT. Пассивный snapshot переносимой SSH-обвязки и локальный исполнитель проверяются отдельно; подробности и границы длительной проверки — [validation](validation.md).
