# Структурированный снимок внутренних задач A.04.02

13 ноября аппаратно прочитаны **47 дескрипторов задач** через короткие адресные
ответы. Все 67 запросов закрылись, набор TID до и после совпал, собственный
буфер освобождён. В прочитанных состояниях нет SUSPENDED; пакетный интерпретатор
`tTclBatch` имеет READY. Это последовательный снимок, не атомарный и не журнал
того, что произошло в старом незавершённом вызове.

Длинный `osTaskShow` оказался непригоден: при корректном конечном nonce внутри
текста найдены исходящие COMMENT-кадры и дубли. Смысловая проверка отвергла
вывод. Отказ от всех дополнительных OUT остановил тот ответ после B; отдельное
продолжение закрыло исходное чтение. Повторного запуска команды при закрытии
не было. Причина повреждения пока не локализована.

## Проверенный способ

| Этап | Операция | Проверка |
| --- | --- | --- |
| Начало | Закреплённые BTT/адаптер/HP, FW A.04.02, пустая очередь, общий lock/guard | Нет чужих USB-дескрипторов и другой операции |
| Код | Живые ABI allocation/call/free, два getter и ready/suspended predicates | Полные ограниченные участки совпадают с закреплённым образом |
| Буфер | Новый `osMemAlloc 4608` | Адрес выровнен, находится в проверенном RAM-окне; старые указатели не используются |
| Список | `taskIdListGet(buffer, 64)` по `0xa005d630` | Количество 1…63, без достижения лимита; TID уникальны и выровнены |
| Описатели | До четырёх `taskInfoGet(tid, destination)` по `0xa0063de0` в одном фиксированном job | Все return=0; destination только внутри своего буфера |
| Чтение | Адресные dump до 128 байт | Свежий nonce, точное покрытие, отсутствие повторов и лишних строк |
| Конец | Повтор списка, сверка состава, free своего буфера, FW/serial | Закрытие всех запросов и восстановление USB |

В буфере первые 256 байт отведены под 64 TID, далее идут 64-байтовые
дескрипторы. Остаток сохраняет запас границ; чужая память не используется
как scratch. Имена читаются отдельно по проверенным указателям, когда нужны.

## Поля дескриптора

Формат big-endian, 16 uint32. Поля восстановлены из кода A.04.02.

| Смещение | Поле | Ограничение интерпретации |
| --- | --- | --- |
| +0 | TID | Должен совпасть с элементом полученного списка |
| +4 | Указатель имени | Сам по себе не является строкой |
| +8 | Приоритет | Проверенный диапазон 0…255 |
| +12 | Состояние | READY при 0; бит 0 означает SUSPENDED по native predicate |
| +20 | Entry point | Точка входа задачи, **не текущий PC** |
| +24 | Сохранённый SP | Не адрес исключения |
| +56 | errno | Сохранённое поле задачи, не системный код HP и не доказанная причина остановки |
| +60 | Delay | Сырое значение; секунды не заявляются |

Повторный состав списка не делает все состояния одновременными. Наличие
READY у интерпретатора не восстанавливает потерянный результат прежнего вызова.
Его guard снят отдельно после сверки текущих задач, исходного штатного слова,
отсутствия старого кода, idle и завершения всех новых операций; исходная запись
сохранена в защищённом архиве. Старый allocation не освобождался.

## Исходники

- [`task_layout_a04.py`](../tools/firmware/task_layout_a04.py) — декодирование и проверки границ без доступа к устройству.
- [`structured_task_reads.py`](../tools/service/structured_task_reads.py) — фиксированный transport для allocation, двух getter и free; без CLI и изменения состояния задач.
- [`quiet_end_reads.py`](../tools/service/quiet_end_reads.py) — политика IN-only после конечной метки.

Транспорт не берёт lock/guard за вызывающий код и не обходит существующую
блокировку. Вызывающий код обязан сохранять allocation/phase, проверять live-код
и не освобождать буфер при неизвестном исходе native-вызова. Аппаратный опыт
выполнялся отдельной ограниченной оркестрацией. Публичные декодер и транспорт
дополнительно сверены офлайн с его реальными байтами и payload; это не второй
аппаратный запуск нового класса.

На HP не отправлялись taskDelete, taskSuspend, taskResume или команды перезапуска.
