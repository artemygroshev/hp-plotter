# Удалённое обслуживание головок HP DesignJet 500

**На A.04.02 выполнен один вызов встроенного восстановления уровня 0 и получен
его маркер возврата. Восстановление печати чёрным этим не доказано.** Процедура
затрагивает четыре головки; отдельная K-очистка не подтверждена. Полностью
автоматическое прохождение штатного Troubleshooting пока не принято.

## Что проверено на плоттере

| Проверка | Результат |
| --- | --- |
| `fpSimulateKey ENTER` | Native ACK и настоящий фрагмент 32×32 с заголовком Ink menu, полученный в том же Tcl job |
| Раздельные кнопка и чтение LCD | Новый служебный job возвращал страницу состояния; одинаковый последующий кадр не доказывал отказ кнопки |
| Постоянный Tcl-сеанс | Короткий FW → serial → close прошёл; более длинный проход отвергнут из-за лишнего `invalid command name "\\x02"` после ответа |
| Большой `osMemDump` | Ответ с двумя блоками по 1024 байта содержал перемешанные строки и отвергнут; рабочие чтения остаются ограничены 128 байтами |
| `svsOnIntervention_set 0` | Одна полная передача, свежие `S` и `R…_0`; повторного вызова не было |
| Исходный конечный `E` вызова | Не подтверждён; возврат функции и закрытие канала учитываются отдельно |
| Физические сопла и чёрный отпечаток | Требуют отдельной проверки на бумаге |

При ожидающем сервисном вызове даже Tcl-комментарии заполнили прямой канал,
после чего OUT завершился тайм-аутом. **Это не основание повторять действие:**
сам вызов уже был передан. Продолжение читалось через IN; после полученного
маркера возврата использовано отдельное закрытие PJL EOJ. После него заново подтверждены FW/serial, нулевые blocking
поля, закрытая крышка и оба буфера LCD. В них сохранилось Printhead warning /
Poor print quality с отметкой Black. Старые, поздние ответы
с другим nonce не назначались новым запросам.

## Как устроен инструмент

[`native_recovery.py`](../tools/service/native_recovery.py) — отдельный
экспериментальный CLI. Он не установлен кнопкой очистки в рабочем GUI.
Переносимая версия оформляет вызов через Tcl `catch`, чтобы ошибка команды не
подменялась заранее напечатанным нулём. Её полный автоматический проход на
железе повторно не запускался: лишняя очистка для проверки программы не нужна.

Перед одной командой инструмент требует:

1. Настроенную локальную root-конфигурацию, закреплённые BTT/адаптер, пустую
   очередь CUPS и свободный USB none/alt0. Общие lock и durable guard обязательны.
2. Свежие firmware A.04.02 и serial. Перед каждым запросом проверяется class ID;
   ограниченно повторяется только пустой ID, без повтора Tcl-запроса.
3. Совпадение четырёх диапазонов кода с закреплёнными SHA256 и наличие штатного
   servicing context. Команды чтения памяти ограничены 128 байтами.
4. Проверенные состояния крышки, механики, blocking faults и busy. `PRINTING`
   и `INK-OUT` сохраняются как многозначные raw-поля, а не преобразуются в bool.
   Разрешён лишь исследованный профиль их значений; он не измеряет объём СНПЧ.

Затем отправляется **один** фиксированный `svsOnIntervention_set 0`, без уровней
1/2, аргументов цвета, произвольных Tcl-команд и параметров температуры/сопел.
Пока нет точного свежего маркера возврата, ожидание выполняет только IN.
После `R…_0` допускается один проверенный кадр PJL EOJ, если исходный `E` не
пришёл. В отчёте явно различаются исходный конечный маркер и отдельное закрытие.
Перед снятием guard нужны две тихие фазы, свежая идентичность, post-status и
полный cleanup USB. Неопределённая запись сохраняет guard и запрещает повтор.

Используйте `native_recovery.py`, `panel_keys.py` и `batch_usb.py` одной версии.
Старый модуль без transport hooks отвергается до открытия USB.

```sh
sudo env HP_PLOTTER_CONFIG=/etc/hp-plotter/config.json \
  python3 tools/service/native_recovery.py --run-level0 --until-utc "$DEADLINE"
```

`DEADLINE` — ISO8601 с часовым поясом, на 12–30 минут вперёд. Это исследовательский
режим для данной проверенной связки, а не команда регулярного расписания.
Возврат native-функции не доказывает прохождение чернил через сопла.

## Граница встроенной процедуры

A.04.02: M68K big-endian; исходный engine SHA256
`c882e68d2eb2462745f1ec984ce8f5ed745d2900587dce6b36acee5b89a1f4eb`.
Бинарный файл HP в репозиторий не включён. Адреса и хеши проверяемых функций
есть в исходнике и [карте возможностей](a04-capabilities.json).

Native bridge вызывает `0xA023E9E0`, уровень 0 выбирает `0xA023E81C`.
В этом preset присутствует маска `0x0f`: отдельного аргумента Black нет.
Вызов проходит ниже диалога IQ и его высокоуровневого учёта попыток;
это не воспроизведение всей пользовательской процедуры Troubleshooting.
Счётчики EEPROM, настройки firmware и низкоуровневые параметры сопел вручную
не меняются. `ssSpit`, `ssWipePens`, `ssScrubPens` не запускаются отдельно.

## Штатный путь HP

В [руководстве HP](https://h10032.www1.hp.com/ctg/Manual/c00748239.pdf),
страницы PDF 72–75, описан `Ink → Troubleshooting`. Плоттер проверяет
выравнивание, печатает образцы и спрашивает о дефектных цветах. Внутри одного
прохода HP ограничивает число попыток очистки тремя. Ни этот предел, ни
предупреждения HP не обходятся автоматическим циклом повторных запусков.

Состояния IQ: 0 INITIALIZING; 1 PRINTING_IMAGE_QUALITY_DIAGNOSTIC;
2 PRINTING_PRINTHEAD_HEALTH_DIAGNOSTIC; 3 UNLOADING_PRINT;
4 CLEANING_PRINTHEADS; 5 CLEANING_DONE; 6 WAITING_FOR_USER_ANSWER.
Старый state6 при ui_handle0 не доказывает активную очистку.

## Кнопки и последующая проверка

[`panel_keys.py`](../tools/service/panel_keys.py) передаёт одну кнопку
ENTER/BACK/UP/DOWN/TOP с проверками кода, текущего полного LCD и nonce.
Его отдельное post-чтение может вернуть панель на страницу состояния.
Поэтому он не реализует автоматическую навигацию или управление всеми функциями.
При мигании нужны обе фазы: основной буфер уже содержал Aligning, пока второй
показывал Printhead warning. Частичный фрагмент не выдаётся за полный LCD.

После завершённого обслуживания и проверки готовности нужен один
[TrueBlack-тест](black-output-check.md), с пустой очередью до отправки.
Приём байтов, возврат сервисной функции и появление чёрного на бумаге — три
разных результата. Бесконечные очистки и повторные тесты не запускаются.
